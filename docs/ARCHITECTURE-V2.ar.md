# النواة المعيارية المحلية — الإصدار الثاني

## ما نُفّذ وما لم يُنفّذ

هذه معمارية قابلة للتطوير عبر وحدات مستقلة، وليست إثباتاً لتحمل 100 مليون مستخدم. بقيت React + Vite حفاظاً على المحرر العامل وتوافق الاستضافة الثابتة. لا توجد حاجة إلى ترحيل Next.js أو فصل نشر Micro-Frontends لتحقيق فصل المسؤوليات الحالي. المشروع أصبح npm Workspaces Monorepo، وحزمه تُبنى معاً كـModular Monolith محلي؛ لا توجد خدمات مدفوعة أو خوادم معالجة للمستندات.

## حدود الحزم

| المسار                     | المسؤولية                                                                            |
| -------------------------- | ------------------------------------------------------------------------------------ |
| `packages/core`            | العقود، التحقق من الخطة، المراجع بين الخطوات، حدود الموارد والتقدم                   |
| `packages/tools`           | 30 تعريف أداة، validators، اكتشاف الوحدات، تحميل محركات التنفيذ والترجمات عند الحاجة |
| `packages/agents`          | عقد مزود التخطيط ومصنعه، ومخطط أوامر احتياطي محدود دون نموذج لغوي                    |
| `packages/storage`         | عقد تخزين غير متزامن، وتنفيذا Memory وIndexedDB                                      |
| `src/features/execution`   | ربط دورة التنفيذ بواجهة React، الموافقة والإلغاء وتنزيل النتائج والحفظ الاختياري     |
| `src/features/attachments` | الملفات الأصلية والتحقق الأولي وتحرير object URLs                                    |
| `src/features/editor`      | تاريخ التعديلات اليدوية والتصدير؛ منفصل عن معالجة الأدوات                            |

لا تعتمد حزم النواة على React. لا يستورد مخطط الأوامر مكتبات معالجة PDF. لا تحتاج الأداة معرفة نموذج الذكاء الاصطناعي أو طريقة التخزين. لا يُستخدم `eval` أو تنفيذ كود ينتجه النموذج.

## مسار التنفيذ

1. يحتفظ المستخدم بالملفات الأصلية محلياً.
2. يدخل أمراً مدعوماً أو يستعمل النموذج المنظم من زر «تنفيذ الأدوات محلياً» في الهيدر.
3. يعيد المزود خطة غير موثوقة؛ النواة تتحقق من الأداة والمعاملات والمراجع.
4. تُعرض المصادر والخطوات للموافقة الصريحة. الرفع واختيار الأداة لا يشغلان المعالجة تلقائياً.
5. ينفذ المحرك كل خطوة في Worker منفصل وينهيه عند الانتهاء أو الخطأ أو الإلغاء أو انتهاء الوقت.
6. تُمرّر نتائج الخطوات كملفات وسيطة، مع التخلص من المراجع التي لم تعد مطلوبة.
7. تُفحص حدود النتائج وترويسة PDF، وتختبر صحة المستندات الناتجة أيضاً عبر PDF-lib في اختبارات الأدوات والمتصفح.
8. تظهر روابط النتائج الفعلية. الأصل لا يُستبدل. لا تُحفظ المستندات تلقائياً على القرص أو في المتصفح.

## الأدوات الحالية

المحركات الثمانية العاملة: merge، split، delete-pages، rotate، reorder، watermark، page-numbers، jpg-to-pdf. توجد اختبارات تنفيذ حقيقية لكل منها. التقسيم ينتج ملفاً لكل صفحة؛ إعادة الترتيب تتطلب جميع الصفحات دون تكرار؛ الصور تدعم JPEG وPNG؛ العلامة المائية تدعم النص ASCII حالياً. العلامات وأرقام الصفحات على الصفحات المدورة تحتاج اختبارات عرض إضافية قبل ادعاء التطابق البصري العام.

الأدوات الـ22 الأخرى لها تعريفات وترجمات مستقلة وحالة `planned`؛ لا يوجد executor وهمي لها. المحرر اليدوي الحالي يظل عاملاً، لكنه لا يعادل تحرير النص الأصلي أو التنقيح الآمن. تنفيذ الأدوات يستخدم الأصول، لا طبقة التعليقات غير المصدّرة؛ يوضح ذلك نموذج المصادر.

## إضافة أداة

- أنشئ `packages/tools/src/modules/<id>/index.ts` بعقد `ToolDefinition` وvalidator صارم.
- أضف `logic.ts` فقط عندما يعمل المحرك فعلياً، وترجمات داخل `i18n`.
- أضف مدخل الكتالوج المناسب إن كانت أداة جديدة في المنتج.
- نفّذ `npm run tools:sync` لتوليد سجل التعريفات وخرائط الاستيراد؛ لا تعدل المحركات القديمة.
- أضف اختبارات للمدخلات الصحيحة والخاطئة وحدود الموارد والنتيجة، ثم غيّر الحالة إلى `ready`.
- الواجهة المنظمة العامة الحالية تستخدم JSON للمعاملات؛ يمكن استبدالها بمحررات خاصة بكل أداة دون تغيير محرك التنفيذ.

Worker موحد للمضيف، وليس نسخ 30 Worker متطابقاً: يحمّل منطق الأداة المطلوبة فقط. العزل هو سياق تنفيذ مستقل، وليس sandbox أمنياً كعزل عمليات نظام التشغيل؛ ثغرة في مكتبة أو استنزاف الذاكرة قد يؤثران في المتصفح. يجب مراجعة المكتبات والتراخيص والأجهزة.

## الحدود الحالية

- 10 ملفات أصلية؛ 20 MiB لكل ملف؛ مجموع عمل 100 MiB.
- 10 خطوات للخطة، و100 نتيجة للخطوة، و1000 صفحة PDF كحد أقصى في أدوات PDF.
- دقيقتان للخطوة؛ الإلغاء ينهي الـWorker حتى أثناء انشغال المكتبة.
- تنفيذ متسلسل، ومهمة واحدة في واجهة التطبيق، وليس ضماناً لسلاسة كل جهاز عند هذه الحدود.
- هذه حدود حماية أولية، لا وعود بدعم مستندات 100MB أو بمنع كل حالات نفاد الذاكرة.

## التخزين والخصوصية

الحفظ في IndexedDB صريح واختياري لنتائج الأدوات فقط، مع تنزيل واسترجاع وحذف. المحادثة وتاريخ التعليقات اليدوية لا يُستعادان بعد إعادة التحميل. الحفظ المحلي ليس تشفيراً ولا نسخاً احتياطياً؛ المتصفح يستطيع حذفه ومستخدم الجهاز المشترك قد يقرأه. فشل الحفظ/الحصة يظهر خطأ ولا يعني نجاحاً وهمياً.

عقد التخزين غير متزامن ليمكن إضافة مزود بعيد لاحقاً. الانتقال للسحابة يحتاج موافقة ومصادقة وصلاحيات وسياسة حذف وفشلاً شبكياً؛ ليست إضافة S3 مجرد تبديل عنوان. لا توجد حسابات أو قاعدة Prisma صورية أو تحقق اشتراكات في العميل. الهوية والاشتراكات تحتاج مكوناً موثوقاً عند تنفيذها.

## التخطيط والذكاء الاصطناعي

المزود الحالي **ليس LLM**. يفهم صيغة محافظة مثل `merge files then delete pages 2 then rotate 90` و`ادمج الملفات ثم دور ٩٠` ويطلب مساراً منظماً عند الغموض. لا يقرأ نصوص المستندات ولا يقيّم أصالتها. لا يوجد Qwen أو Gemini أو Phi أو كشف تزوير أو ربط API في هذه الدفعة. عقد `AgentProvider` ومصنعه يسمحان بإضافة مزود محلي متحقق منه؛ تظل نتيجة أي مزود خاضعة للتحقق والموافقة في النواة.

## اللغات والعمل دون اتصال

توجد 29 لغة في كتالوج المنتج، لكن الواجهات المترجمة فعلياً هي العربية والإنجليزية والفرنسية. ترجمات كل أداة ملفات مستقلة تُحمّل عند الحاجة مع fallback صريح إلى الإنجليزية؛ لا تُعرض اللغات الـ26 كترجمات مكتملة.

بناء الإنتاج يولّد Service Worker ذا نسخة مرتبطة ببناء الواجهة، وPWA manifest. يخزّن shell وموارد التطبيق الثابتة فقط؛ لا يُخزّن ملفات المستخدم أو رسائل chat أو استدعاءات API أو نماذج خارجية أو إعلانات. الأدوات التي اكتمل تحميل ملفاتها وتخزينها أثناء الاتصال يمكن تشغيلها لاحقاً دون اتصال؛ أول زيارة لا تعني تنزيل جميع الأدوات أو النماذج. توجد حدود لحجم وعدد ملفات cache. المتصفح قد يمسح البيانات، وميزة Offline غير مفعلة في dev أو ملف HTML المحمول.

## النشر والنمو العالمي

`npm ci && npm run build` ثم نشر `dist` على استضافة ثابتة مناسبة. لا توجد حاجة إلى خادم PDF حالياً. يجب التحقق من شروط الاستضافة التجارية وحصص التوزيع. لا يُعد عدد الملفات أو استخدام Zustand/Web Workers اختبار تحميل عالمي. أحجام النماذج وتوزيعها واتصال المستخدمين وقدرة أجهزتهم تظل قياسات مستقلة.

ما زال مطلوباً قبل إطلاق المنتج الكامل: المحركات الـ22، مزود LLM وتوافق الأجهزة، اللغات المتبقية، إمكانية الوصول للمستندات، اختبارات أمان ومتانة وأجهزة فعلية، قياس الحركة والتكاليف، والحسابات/الاشتراكات وفق سياسة واضحة. الإعلانات والدفع لا يعملان دون اتصال ولا يمكن تأمين استحقاقاتهما بـlocalStorage.

## التحقق

- `npm run lint`: ESLint ورفض `any` الصريح في TypeScript.
- `npm run typecheck`: TypeScript Strict.
- `npm test`: العقود والأدوات والتخزين والمخطط والتراجع والتحقق من الملفات.
- `npm run build`: كود الواجهة والـWorkers، وفحص syntax للـService Worker المولّد.
- `npm run test:e2e`: المحرر السابق + التنفيذ الحقيقي + الحفظ + الإلغاء + مسار Offline عند اختباره على build الإنتاج.
- GitHub Actions مجهز لتشغيلها بعد رفع التغييرات؛ لم يُختبر تشغيله على حساب GitHub من هذه البيئة.
